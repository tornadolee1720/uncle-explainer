# 案例：《谷歌給蘋果的兩百億》（2026-10-31，28 秒）

模板檔第一版的示例片全是圖形、滿屏 3D、底色難看。之後按原版的做法，用真素材手寫了這條短片。kit 的預設畫風就是照這條和原版（`../ai-burn-money/`）返工的。

**不要照著它的鏡頭順序做新片。** 學的是：實拍和新聞是主角、底只有一張細斜紋織物、圖形只用來演錢和關係、每一鏡都接住上一鏡。

- `script.txt`：文案（豆包 2.0 配音，一次合成，27 秒；字級時間用 faster-whisper 對齊）。
- `film_index.html`：整條片的頁面，手寫檔最小的樣子（不用 film_base，只有 `window.ready` 和 `window.seek(t)`，`render.mjs` 直接渲）。素材和成片抽幀都有版權，不隨倉庫給，頁面只用來讀。
- `fabric.py`：細斜紋深藍織物底的生成指令碼（kit 的 `make.py` 照它改的）。
- `matte_full.py`：CPU 上整幀摳人（和 `matte.py` 同一個 ISNet 模型；沒有顯示卡時用）。

## 為什麼這麼做（對著第一版示例片的毛病）

- **不再全是圖形**：28 秒裡有 6 鏡是真東西：官方廣告實拍 2 段、4 篇新聞原文、當事人實拍摳像。圖形只有圓盤連線、金色數字、兩根柱子三樣，都在演錢。
- **不要滿屏 3D**：透視只有一種：新聞攤在桌面上。其餘都是平的，靠鏡頭推拉和前後層出空間。
- **底色**：全片一張很細的斜紋深藍織物，中間略亮；只在皮查伊身後換成谷歌藍的同一種織物。沒有紫底、沒有大團彩色光、沒有浮塵。
- 數字一律金色漸變 Bebas Neue，中文單位用數黑體；原文刷黃用正片疊底，從左往右刷。

## 和原版比還差的（交片前並排比過）

- 原版有當事人原聲收尾（扎克伯格），實拍比例更高；這條 28 秒沒留原聲。影片長一點就要留一段原聲。
- 原版柱子那段是酒紅底、柱子站在臺上；這條用深藍織物 + 倒影，乾淨但沒那麼"算總賬"。

## 做的時候踩的坑

- **交出去的第一版 1080p 結尾 3.5 秒是空的**（金句和字幕都沒了）：出 1080p 前改了一處 HTML，把第 7 鏡的 `</div>` 改壞，第 8 鏡和字幕被套進第 7 鏡一起藏了。改完只看了兩張靜幀。現在的 `film_index.html` 是修好的；`render.mjs --video` 渲完會自動報空畫面。教訓：改了頁面就整片重渲 720p 從頭看到尾，再出 1080p。

- YouTube 只截一段：`--download-sections` 和 HLS 格式都會斷，用 `-f 137`（https dash）拿直鏈再 `ffmpeg -ss -t -c copy`。見 `references/sourcing.md`。
- 映象下摳像模型會斷，續傳可能拼壞檔案：對 `X-Linked-Size` 和 sha256。
- `render.mjs` 的本地伺服器根目錄是影片目錄，`../` 引用的字型會 404：字型拷進影片目錄。
- 蘋果廣告裡 Safari 圖示那鏡只有 0.6 秒：開頭只能放慢用。
- 頁面要按 `innerWidth/1920` 縮放整個舞臺，不然 720p 渲出來只有左上角。
