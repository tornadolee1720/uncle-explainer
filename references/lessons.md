# 實踐中踩過的坑

示例片做了六個版本，下面是每一步暴露的問題和最後的改法。遇到新情況，先看這裡有沒有類似的。

## 風格和質感

| 問題 | 為什麼不行 | 改法 |
|---|---|---|
| 背景用 AI 生成的電影感圖（熔爐、賭場、神殿） | 一眼就假，顯得廉價 | 舞臺只用中性紋理；人物和事件用真實素材 |
| 元素各自演入場：彈出來排隊、重排成田字格、貼皇冠、打字機、掃光 | PPT 感 | 東西自己只淡入（約 0.25 秒）或切過來就在；大運動交給鏡頭和原地換狀態（`motion.md`） |
| 清楚的實拍上壓標題、貼名牌框 | 同樣廉價 | 只留兩種壓法：人摳出來站在巨字前面；實拍壓暗去色退成底、字是主角 |
| 用低清百科影片 | 畫質一看就不行 | 換官方 1080p 宣傳片和紀錄片 |
| 整張平面一起慢慢縮放（沒有目標、多半往外拉） | 廉價，像幻燈片在呼吸 | 鏡頭在有前後層的舞臺裡走：快速換位到正在講的東西，再慢漂往裡推 |
| 把慢推全刪掉 | 三分之二的時間整屏定住，影片死了 | 同上；交片前用 `motion_check.py` 量 |
| 每個數都滾 | 裝飾，不是內容 | 只在“累加”本身是意思時滾，一支片一兩次，滿位數、按十億取整 |
| 英文副標題、章節牌、來源小字到處都是 | 太多小字，看著累 | 一鏡最多一個短的中文標籤；一幀最多一組眉題 |

## 素材和邏輯

| 問題 | 為什麼不行 | 改法 |
|---|---|---|
| 唸到公司名就切航拍 | 看不出是誰家的樓 | 身份要在畫面裡：臉、logo、寫著名字的新聞標題 |
| 鏡頭之間硬切，素材只停零點幾秒 | 前言不搭後語，前因後果看不出來 | 先寫導演表，逐鏡寫“承接”一列；實拍至少停 1.5 秒左右 |
| 資金關係圖中間插一段全屏新聞片 | 打斷關係圖 | 新聞做成小卡，從箭頭旁彈出，讀完縮回去 |
| 直接插 CEO 原聲 | 觀眾不知道他是誰、為什麼在這說 | 先加鋪墊句，畫面上也做交接 |
| 結尾放一段好看但和內容無關的航拍 | 跟論證沒關係 | 結尾回到全片那個數字和開頭那幾家公司 |
| 收到修改意見後換了一種風格重做 | 偏離了已經認可的版本 | 在原版上逐鏡改；改動多時先列清單確認 |

## 動效、剪輯和包裝

和參考片放在一起看，第五版差得很遠。逐幀量了參考片的鏡頭運動以後，問題和改法如下（原理見 `motion.md`）：

| 問題 | 為什麼不行 | 改法 |
|---|---|---|
| 人和圖形從不一起動 | 參考片最招牌的動作全沒有 | 用當事人的實拍摳像演：人站在巨字前面、人身後換背景、橫推換人、卡片在人旁邊冒出來 |
| 東西擺好以後整屏定住 2–9 秒 | 死 | 每鏡有機位：快速換位 → 慢漂 → 下一刀 |
| 新東西一張張砸到最上面 | 元素在演 | 東西早就擺在世界裡，鏡頭去找它（新聞卡鋪成桌面、鏡頭滑過去；關係網裡鏡頭搖去找正在說的那家） |
| 只有淡入和硬切，沒有前後層 | 平 | 分層相機（遠的動得少）、方向運動模糊、景深；上一鏡虛化當底、平面倒成桌面 |
| 橫推換人的前幾幀露出了採訪者 | 原片的切點比入點晚 | 摳像前逐幀查切點，`matte.py --from` 跳過 |
| 巨字被人擋住一半 | 人在原片裡走動 | 按每幀頭肩中心把人釘在兩組字的空當裡（`matte_clean.py` + `stage25d.js` 的 track） |
| 畫框底部露出原片燒進去的字 | 抽幀沒裁 | 抽幀時放大裁掉 |
| 一次批評變成了全域性禁令 | “慢推廉價”被理解成“不許動”，結果影片死了 | 先分清是手法不對還是做法不對，拿參考片同一個手法的連續幀對照 |

## 開頭

| 問題 | 改法 |
|---|---|
| 沒資訊量的空鏡開場 | 用關鍵詞釘在中央的快閃，墊在第一句話下面 |
| 新聞卡隨機亂疊 | 關鍵詞固定在螢幕正中，周圍的出處在換 |
| 旁白前空等兩秒放快閃 | 縮到 0.3 秒就開口 |
| 搜尋引擎攔截截圖 | 用核實過的文字自己排效果圖，不模擬實網站 |

## 聲音

| 問題 | 原因 | 改法 |
|---|---|---|
| 語速時快時慢 | 每句前後帶著 0.2–0.6 秒靜音，再加上停頓 | 每句切掉首尾靜音，停頓只由 gap 決定 |
| 語速聽著急促 | 切掉靜音後又拉了 1.1 倍 | 保持原速 |
| 配樂“怪” | 緊張滴答樂和放映機聲 | 去掉，只留平穩的底樂和輕翻書聲 |
| 原聲裡有“異響” | 句尾砍掉半個詞；截進了一段數字靜音 | 剪口按波形定 |
| 字幕和卡點全錯 | 對齊指令碼用檔名前三個字當鍵，b10b 覆蓋了 b10 | 鍵用完整編號 |

## 工程

| 問題 | 改法 |
|---|---|
| 交出去的檔案打不開（合成沒寫完） | 每個檔案用 ffprobe 驗證過再交 |
| 合成時 ffmpeg 卡死 | 在一個大濾鏡圖裡同時讀帶畫面的 mp4、圖片和多條音軌會互相等待；音訊先抽成 wav，字幕和音訊分開合成 |
| yt-dlp 403 | `pip install -U yt-dlp` |
| edge-tts 403 | `pip install -U edge-tts` |
| 實拍黑屏或空框 | 新素材的幀數沒登記 |
| 停住的畫面露出下一個鏡頭 | 抽幀時出點壓在了鏡頭切點上 |
| 熒光筆和文字對不齊 | 字型載入完以後再量、再截 |

## 手法庫

- 這份 skill 一開始只有原則和工具，鏡頭全靠現寫：能力強的模型駕馭得住，弱一點的模型每條片都會重新摔一遍同樣的跤，品質不穩。
  → 從第六版拆出底座 `film_base.js` 和手法庫 `moves.js`，起步用 `starter/`。手法只管動作，畫面由影片傳；每個手法寫清“說的是 / 不適配的時候”；呼叫要寫 why；`render.mjs --moves` 查用量和與上一支片的重合。
  → 複用是為了穩定品質，不是為了模板化：先想這一鏡要說什麼，再找最對得上的手法；只是差不多就手寫，不要為了出片去湊手法。

## 模板檔

- 有了手法庫，每一鏡的畫面還是要現寫，對模型的要求還是高。
  → 加模板檔 `kit/`：一支片 = 一張鏡頭表，每鏡選一個場景、填內容、寫 `says`；鏡頭、出現方式、前後層、字號顏色都由模板管。時刻寫成 `'@句:詞'`；`render.mjs --check` 用文字報錯和提醒（有的模型看不了圖），`--sheet` 每鏡三幀拼一張圖。硬規則在 `references/rules.md`。目標是讓弱一些的模型也能穩定出片，這一點還沒實測過。
  → 原來的手寫檔（`film_base` + `moves` + `stage25d`）留著：模板對不上的那一鏡寫 `scene:'custom'`，或者整條手寫。
  → 選場景仍然按“這句話在說什麼”，不按順序套。模板是詞彙，不是鏡頭順序。
- 模板檔第一版的示例片全是圖形：沒有真人、真新聞；斜著的 3D 卡片牆、手機、標題牆；整屏紫、青、酒紅底和大團顏色光；織物底是一塊塊的噪聲；前景有浮塵。
  → 按原版的做法，用真素材手寫了一條 28 秒的《谷歌給蘋果的兩百億》（`examples/google-apple-20b/`）。kit 的預設畫風照這條和原版返工：細斜紋深藍織物底；`tone` 只留 navy、charcoal、wine；顏色光只給 `person`；去掉浮塵；3D 改平，只留“新聞攤在桌面上”和“倒成桌面”兩種透視；照片圓盤；原文攤在織物上，不整屏白。
  → 交片前和 `examples/ai-burn-money/frames_1fps.jpg` 並排抽幀比，是硬步驟，不是可選。
- 交付時只籠統寫了“用了 skill”，其實谷歌那條只用了截新聞和渲染兩樣。
  → 交付說明裡寫清實際用了哪一檔、哪些指令碼。
- 直式《英偉達拒絕老黃迴歸》連交四版被打回（"不好看""特效老重複""風格怪怪的""開頭廉價"），每版都在憑印象改進場的緩動。
  → 把參考片和自己的同類鏡頭放大並排看，差距一眼就出來了，而且不在緩動：口播壓了黑、強調色是金字棕邊、東西小、道具是程式碼畫的、落定後到處在晃。
  → 開工第一步先並排對照、寫出差距（`SKILL.md`"先選畫幅"一節）；規矩收進 `kit/VERTICAL.md` 的 vpro 一節。
