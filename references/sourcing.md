# 素材與證據

## 優先順序

1. **當事公司的官方片**（YouTube 官方頻道，1080p、乾淨、沒有新聞條）：產線、機櫃、資料中心、釋出會集錦。
2. **大媒體的紀錄片**（Bloomberg Originals 這類）：採訪近景很漂亮，自帶名牌，航拍可以當氣氛鏡。
3. **新聞臺**（CNBC、Bloomberg TV 等）：底部有新聞條，只在兩種情況下用：截當事人的原聲，或者新聞條本身就是證據（比如“NVIDIA TO INVEST UP TO $100 BILLION IN OPENAI”）。
4. **新聞和報告原文截圖**：用來證明可能被質疑的數。
5. **Wikimedia Commons**：只用來取 CC 許可的人物照片（做圓盤裡的摳像）和 logo，要註明作者和許可。它上面的影片畫質普遍太低。
6. **生成圖**：中性紋理；或者演一個拍不到的具體比喻物件（一枚幣、一座樓、一條蛇吞大象），摳出來放進前後層，寫實的標“AI生成”。不做電影感氛圍大片。

這些影片大多有版權，只做評論、解讀性質的引用。**每條片都要把全部素材的出處寫進簡介**（格式參考 `examples/ai-burn-money/CREDITS.md`），並提醒使用者存在被投訴的風險。

## 找片到抽幀（`scripts/footage.py`）

1. `search "關鍵詞"`：帶上公司名和 b-roll、keynote、official、data center 這類詞，看頻道名，挑官方的。
2. `get <id>`：下載 1080p。長影片（釋出會全程、播客）只下需要的那一段：`--section 01:11:40-01:12:12`。被 403 攔住時，先 `pip install -U yt-dlp`。
3. `sheet <影片>`：拼一張帶時間碼的聯絡表，用眼睛挑鏡頭。挑的標準是這一鏡能不能讓人認出它說的是誰、是什麼。
4. `scenes <影片> --from a --to b`：查鏡頭切點。入點和出點都要落在同一個鏡頭裡，避開片頭片尾、幻燈片和主持人（釋出會集錦里人物前面常常是一張幻燈片）。
5. `extract clips.json`：抽成 30fps 幀序列。要裁掉臺標、角標、原片燒進去的說明字時用 zoom/ax/ay 引數。抽完逐幀查一遍切點（相鄰兩幀差很多的地方）：第一幀和最後一幀不能是別的鏡頭，中間藏著的切點也要剪掉，或者留著當作底下實拍的一刀。
6. 把幀數登記進渲染程式碼（`counts.json` 裡有）。漏登記的話會取到不存在的幀，出現黑屏或空框。

## 當事人的摳像（`scripts/matte.py` → `matte_clean.py`）

人和圖形一起動的那些手法（人站在巨字前面、身後換背景、橫推換人、卡片在旁邊冒出來），都要當事人的實拍摳像。

- **挑一段沒有切點的實拍**，比這一鏡要用的時長長一點。釋出會的臺上、採訪的近景都好用；純色或暗的背景摳得最乾淨。挑有動作的那一段對上臺詞（說“全世界最值錢”時他正好張開雙手）。原片不夠長可以放慢到 0.8 倍，再慢就看得出來了。
- 抽幀以後先看切點：`matte.py` 會列印“可疑切點”。採訪片常常前幾幀還是採訪者，用 `--from` 跳過，不然橫推換人的那一下會露出別人。
- 模型：`isnet-general-use` 在 GPU 上約 0.25 秒/幀，邊緣夠用；`birefnet-portrait` 頭髮更乾淨，但在 8GB 影片記憶體的卡上要 10 秒以上一幀。用 GPU 版 onnxruntime 時先 `preload_dlls()`，不然會悄悄跑在 CPU 上。
- `matte_clean.py`：去掉臺上的線、小塊；貼著人的椅背去不掉時用 `--cut-left` 整列抹掉；寫出每幀頭肩的中心（`box.json:cx`），放人時按它對齊，人在原片裡走動，畫面裡就釘住了。
- 名牌、臺標不用管，摳的時候自然就去掉了。摳像也是引用的畫面，出處照樣寫進清單。

## 新聞原文（`scripts/snap_news.mjs`）

- 用英文搜真實報道。優先找能直接開啟的頁面：通訊社的轉載頁、科技媒體、財經門戶。有的站會攔截自動訪問，或者彈驗證碼。
- 截圖流程：
  - 攔掉廣告和同意彈窗的域名（不要攔掉所有第三方，會把網頁字型也攔掉）；
  - 去掉所有 fixed/sticky 浮層；
  - 把標題滾到離頂部約 140px；
  - 等字型載入完；
  - 先量關鍵詞的框，再截圖。
- 折行的關鍵詞會給出兩個框，熒光筆要按行一段一段刷。
- 被攔住時不要硬截。用核實過的文字自己排一個通用樣式的效果圖，不仿任何真實網站。

## 當事人原聲

- **找原話**：`yt-dlp --skip-download --write-auto-subs --sub-langs en` 拿自動字幕，在字幕裡搜關鍵詞定位大概時間；只下那一段，再用 faster-whisper 識別出每個詞的時間。
- **剪口以波形為準**（`footage.py wave 檔案 起 止`），Whisper 給的時間會偏零點幾秒：
  - 開口前留 0.05 秒；
  - 句尾要等最後一個字的能量完全落下去，砍掉半個詞聽起來就是一聲“異響”；
  - 中間如果有數字靜音（低於 -75dB），說明原片在這裡剪過，不要截進來，否則會突然“斷電”再猛地進人聲。
- 分段下載的音軌偶爾會解碼出錯（ffmpeg 報 `aac decode_band_types`）。用 `get --audio` 單獨再下一次音訊，按畫面對齊（兩條音軌做互相關，算出偏移）。
- 一段原聲裡跳著剪幾句可以接受，接縫要落在停頓處。
- 原聲畫面用全屏；當成反應梗時，放在壓暗背景上的小窗裡。

## 下載踩坑（做《谷歌給蘋果的兩百億》時碰到的）

- YouTube 只要一小段：`--download-sections` 和 HLS（m3u8）格式直連都會斷。先 `yt-dlp -F` 找 https dash 格式（1080p 一般是 137），`yt-dlp -f 137 -g URL 2>/dev/null` 拿直鏈，再 `ffmpeg -ss 起點 -i 直鏈 -t 秒數 -c copy out.mp4`。不用 cookies。
- 映象下大模型會斷：`curl -C -` 續傳可能把檔案拼壞（比該有的還大、載入報 protobuf 錯）。先 `curl -sIL` 看 `X-Linked-Size`，迴圈續傳到大小對上，再對 sha256。
